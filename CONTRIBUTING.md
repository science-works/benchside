# Contribute to Benchside

We welcome researchers' scientific role profiles, improvements to existing
roles, synthetic evaluation examples, documentation and bug reports. You can
ask your coding agent to prepare a pull request; you do not need to edit YAML
by hand.

## Propose a scientific role profile

Start with the scientific job it should help with, the intended users and the
limits of its advice. Explain how it differs from an existing role. Include a
short synthetic conversation showing both helpful behaviour and a failure it
should avoid. Never include private research records, participant details,
credentials or unpublished findings in a public PR.

Role definitions live in `content/personas/*.yaml`. Use an existing profile as
a template; `pi.yaml` is the broad supervisor and `pi-hypothesis.yaml` is the
focused hypothesis reviewer. Define its title, description, version, stance,
voice, expertise, useful questions, failure modes, escalation rules and flow.
Make a hypothesis optional unless that role specifically requires one. Keep
recording and consent rules intact, and preserve the researcher's decisions.

Prefer existing scientific record types. A new record type or role identifier
can also require schema, reporting/receiver validation, packaging and test
updates; adding YAML alone does not establish end-to-end compatibility.
Maintainers can help scope these changes during review.

Have your agent:

1. Inspect the repository and choose a focused change on a branch.
2. Edit the source profile and relevant synthetic evaluation prompts.
3. Run `uv run bench compile`, relevant tests, then the repository's CI checks.
   Generated CLI skills come from the YAML; app references are generated by the
   release builder. Do not maintain conflicting copies by hand.
4. Open a PR describing the scientific purpose, before/after behaviour,
   validation and remaining limitations. Keep human judgement and source
   grounding visible; passing code tests does not prove scientific quality.

If you prefer, open an issue with the role proposal and examples first. Profiles
are reviewed before inclusion and released through the normal package update.
No community account is required to use Benchside privately.

See [our purpose and planned community](docs/community.md). Shared workaround
search and researcher matching are future work, separate from contributing a
role through GitHub today.
